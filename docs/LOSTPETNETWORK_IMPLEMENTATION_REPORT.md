Prefabs generated: `PetCard`, `ReportRow`, `MapPin` (`Assets/_Project/Prefabs`).

### Design assets
* **Fonts** — Fraunces SemiBold (headings) and DM Sans Regular/Medium/Bold (body). Downloaded from `github.com/google/fonts` (SIL Open Font License;
  licence files kept in `Art/Fonts`). Google ships them as variable fonts, so static instances were generated with `fonttools`
  (wght 600/opsz 36 for Fraunces; wght 400/500/700 for DM Sans) and converted to TextMeshPro dynamic font assets.
* **Icons** — 25 icons exported from the Figma icon geometry (white strokes, tinted in Unity).
* **Photos** — the 3 pet photos and the sign-in hero generated earlier in Figma (AI-generated sample images), exported from the Figma file.
* **Not imported** — a generated portrait avatar (unused, deleted). Real users have no avatar upload yet; the Profile screen shows initials.

### Architecture / important changes
* Layers: `UI` → `Services` (`Auth`, `Profile`, `Reports`, `Supabase`). Assemblies: `LostPetNetwork.Services`, `LostPetNetwork.UI`, `LostPetNetwork.Editor`, two test assemblies.
* **Real vs mock is separated by an interface**: `IReportRepository` with the only implementation `MockReportRepository` (in-memory). Swap `ReportServices.Repository`
  when Supabase tables exist.
* Authentication code (`AuthService`, `SupabaseHttp`, `SessionStore`, `AuthValidator`) was **not rewritten**. Changes to existing files:
  `ScreenManager` (extended: back stack, tab bar, guard), `ProfileService` (cached profile + cleared on sign-out), `Theme` (gold colours), `AuthValidator` unchanged.
* The scene is generated by an editor tool so it is reproducible: menu **LostPetNetwork ▸ Build App UI**
  (`Assets/_Project/Editor/AppUIBuilder.cs`, `AppUIScreens.cs`, `UiKit.cs`). It replaced the earlier `AuthUIBuilder.cs`.
* Player settings: bundle/package id `com.lostpetnetwork.app`, portrait, iOS camera usage description. Active build target is now **Android**
  (this also touched `Assets/Settings/UniversalRP*.asset` automatically).
* Deliberate deviations from Figma (documented, not silent): no notification bell, no share button, no filter-sliders button, no camera flash,
  no map "locate me" button (none of these have a backend/hardware behind them yet); the Home hero no longer claims "128 pets reunited this month"
  (a made-up statistic); the photo drop-zone border is solid instead of dashed; Profile settings rows are labelled "Soon" and are not tappable.

## F. Backend gaps (Supabase)

Existing and verified: `auth.users`, `public.profiles` (+ RLS, trigger `handle_new_user`), email confirmation ON.
Missing for the remaining features:
1. `reports` table (type, status, species, name, breed, description, location text + coordinates, occurred_at, owner id) with RLS: owners write their own rows; **other users may read only non-private columns** of active reports.
2. `report_photos` + a **Storage bucket** (e.g. `report-photos`) with policies: authenticated upload to own folder, public/signed read, size/type limits.
3. `contact_requests` table (report id, requester id, message, status) with RLS; the owner decides whether to reveal contact details. Phone numbers must never be public.
4. A way to show the reporter's **display name** to other users (profiles are currently private by RLS) — a view or a narrow select policy.
5. Optional later: PostGIS or a bounding-box index for "near me", `pgvector` + an Edge Function for image matching, push notifications.
6. Auth configuration: custom SMTP, *Reset password* template containing `{{ .Token }}`, shorter JWT expiry if desired.

## G. Security and technical debt

* **Token storage** — `SessionStore` writes the access + refresh token to `PlayerPrefs` (plain text on disk). Passwords are never stored.
  A Keychain/Keystore-backed store needs a native plugin and device testing; I did not add one because it cannot be verified reliably here.
  Mitigation to consider: store only the refresh token.
* **Access tokens outlive sign-out** for database reads until they expire (≤ 1 h) — inherent to JWTs.
* Only the **publishable key** is in the client (`SupabaseConfig.cs`); a unit test asserts the `sb_publishable_` prefix. No service-role key, passwords or tokens in source (grep checked).
* RLS and the migration were not changed in this phase. Cross-user isolation was verified in the previous phase and the profile update path ran under RLS again here.
* **Mock data** — everything in Home/Explore/Map/My reports/Details (except the owner's name) is demo data and is labelled "Demo data" in the UI.
  Reports created in the app disappear when the app closes.
* Camera: only `WebCamTexture`; no gallery picker, flash or autofocus control. Permission flows exist for Android/iOS but are unverified on devices.
* Map is an illustration; distances are sample values.
* The Game-view screenshot helper (`UiTestDriver`) and builder are Editor-only and excluded from player builds.
* TextMeshPro "Essential Resources" were imported into `Assets/TextMesh Pro` (needed; should be committed).
* iOS: bundle id and camera usage text are set, but no iOS build was attempted (needs Xcode).
